## Actual layout and API changes

QUIC prefix and connected-application entry files contain the existing composed
locals. The application role files now live in `application/local/`. Stream
numerical operations have been split into `stream/imp/`, with the old public
import preserved by a direct re-export. No forwarding progress controller was
introduced. Host HTTP/3 computations live in `http3/imp/wire.rs` alongside the
existing global and direct locals.

TLS transcript definitions are physically in `handshake/global.rs`; the owned
handoff composition is in `handshake/global/owned.rs`. Individual computations
live in `handshake/imp/transcript.rs`. Prior public global imports are direct
re-exports. This layout does not add TLS states, phase flags or communications.

The Host library now owns `connection::handshake`: real allocation, attachment
and canonical projected execution were moved from the CLI. The CLI re-exports
this function, rather than maintaining a separate implementation. This is a
reusable authenticated prefix, not a finished high-level HTTP/3 application SDK.
The application loop and real network Hibana transport remain unfinished.

The `imp` naming follows an actual standard-library example: Rust
[core::num::imp](https://github.com/rust-lang/rust/blob/main/library/core/src/num/imp/mod.rs)
separates numerical routines from the API. It is not a claim that all standard
library modules use the same directory convention.
